音聲買得多了，資料夾就會越來越長。有時只記得封面和聲優，卻想不起作品名字；有時昨晚聽到一半，第二天又要拖著進度條找位置。檔案都在自己的硬碟裡，找到它、接著聽，卻還要費一點功夫。

Kikoto 是我做的一個開源音聲庫，想把這些事情放到一起：用封面瀏覽作品，按聲優和標籤找音聲，記下想聽的列表，再從上次停下的地方繼續。把它部署在電腦或 NAS 上，瀏覽器和 Android、iOS 客戶端都能存取同一個庫。下文按 Kikoto v0.10.0 介紹。

如果想先看看介面，可以打開[線上演示](https://kikoto.yexca.net/)。演示站唯讀，展示的是 DLsite 的免費全年齡作品；Kikoto 本身不提供音聲資源，用來管理自己購買的作品。

## 把資料夾變成能搜尋的媒體庫

Kikoto 會掃描你指定的音聲目錄，從資料夾名稱裡的 `RJ` 等作品編號辨識作品，再同步 DLsite 的標題、封面、社團、聲優和標籤。原本的目錄可以繼續使用，不必先把所有檔案手工錄入一遍。

可以把入庫過程理解成兩條線：一條找到硬碟上的檔案，另一條補齊作品資訊，最後在同一個媒體庫裡瀏覽和播放。

```mermaid
flowchart TB
    A["自己的音聲資料夾"] -->|掃描檔案| C["Kikoto 媒體庫"]
    B["DLsite 作品資訊"] -->|同步封面與介紹| C
    C --> D["搜尋與收藏"]
    C --> E["播放與接著聽"]
```

想聽某位聲優的作品，可以直接搜尋名字；只記得社團、標題的一部分或作品編號，也能找到。想更精準一點，可以用 `tag: 癒し`、`circle:`、`va:` 分別限定標籤、社團和聲優，在前面加 `-` 則排除匹配的作品。標籤已經有對應的多語言名稱時，用其他語言的名稱也能匹配。

平時可以按推薦、最近新增、評分、銷量或發行日期瀏覽；不想挑的時候，也可以隨機看看。點進社團或聲優頁面，就能順著自己喜歡的創作者繼續找作品。

![Kikoto 英文介面的作品詳情與檔案目錄](https://github.com/yexca/picx-images-hosting/raw/master/2026/10-kikoto/work-detail-en.webp)

詳情頁把封面、製作資訊和檔案目錄放在一起。音軌可以直接播放，同目錄裡的圖片、文字和字幕也能預覽，檢視附帶內容時不用再切回檔案管理員。

多語言作品有兩個獨立選擇：**元數據語言**在有對應內容時改變標題、簡介和標籤的顯示，**目錄版本**切換實際檔案。例如用中文標題瀏覽日文音軌，或者打開已經儲存的英文版目錄。切換文字的顯示語言，不會改變音訊本身。

## 聽到哪裡，下次就從哪裡繼續

點一條音軌開始播放，同資料夾的其他音軌會進入佇列。瀏覽別的作品時，播放仍然繼續；播放器可以收起，需要看歌詞或調整佇列時再展開。

Kikoto 會儲存收聽進度。下次打開作品，點「繼續播放」就能回到上次停下的位置，不必先猜是哪一條音軌。想從頭聽某一條時，直接點那條音軌即可。

![Kikoto 英文介面的播放器與歌詞](https://github.com/yexca/picx-images-hosting/raw/master/2026/10-kikoto/player-lyrics-en.webp)

作品附帶 LRC、VTT、SRT 等字幕檔案時，可以像歌詞一樣跟著音訊看。帶時間軸的句子還能點擊跳轉，聽漏了一句，點回去就好；有多個匹配的歌詞檔案時，也可以自己選擇。

沒有歌詞的音軌，可以在作品的「管理歌詞」裡用語音辨識轉寫成帶時間軸的歌詞，預覽確認後再加入。已有的歌詞，以及標題、簡介、標籤和檔名，也能用「AI 翻譯」補上其他語言。歌詞按語言分別儲存，播放時優先使用自己設定的元數據語言；AI 生成的歌詞，播放器也會標出來。

轉寫和翻譯需要管理員先在「設定 → 語音辨識與大語言模型」裡接入服務，可以用 OpenAI 相容介面、Ollama 等，也可以用 [Kikoto Helper](https://github.com/yexca/kikoto-helper) 在 Windows 電腦上本機執行模型。使用外部服務時，記得先看看對方的使用條款。

播放器還支援調速、佇列排序、後退 10 秒和前進 30 秒。睡前聽可以設定睡眠定時器，並讓它停止後往回倒一點，第二天更容易找到還記得的段落。

電腦瀏覽器可以把歌詞放進畫中畫小視窗；Android 客戶端獲得懸浮窗權限後，可以在其他應用程式上方顯示歌詞；iOS 客戶端則用畫中畫視窗顯示。看歌詞不一定要一直停留在播放器頁面。

## 把想聽和聽過的作品整理起來

資料夾通常只能告訴你「有哪些作品」，收藏架還可以告訴你「準備聽什麼、正在聽什麼、已經聽過什麼」。作品卡片和詳情頁上都有快速標記，可以標為想聽、正在聽、已完成、重聽或已擱置；旁邊還能給作品打一到五星的個人評分。作品也能放進自己建立的收藏列表，例如睡前聽、喜歡的耳かき、想重聽的劇情；動態列表則按標籤自動收錄作品。

個人標籤可以加在作品、社團和聲優上。評分、收藏和標記會參與推薦：打了四五星的作品會讓相似的作品更靠前，一兩星則讓它們靠後。帳號之間分別儲存個人的收藏與收聽資料，同一個庫也可以有不同的整理方式。

## 不知道聽什麼，就去「發現」看看

「發現」頁面用來找下一部想聽的作品。「為你推薦」每次從本機作品裡抽幾部：可能喜歡的、平時很少聽的，以及喜歡過卻很久沒聽的，每張卡片都寫著抽中的理由。在社團、系列或聲優頁面點鈴鐺訂閱後，他們的新作會出現在「新作」裡；「排行榜」追蹤 DLsite 排行榜的名次變化。

想回顧自己聽了什麼，可以打開「資料面板」。這裡有一年的收聽日曆、年度報告，以及和整個媒體庫對比得出的口味畫像，能看到最常聽的作品、聲優、社團和標籤。

## 檔案分散在不同地方也能管理

作品放在多塊硬碟上時，可以使用儲存池，把每塊盤作為獨立的媒體位置加入。某塊盤暫時沒接上，會顯示離線，掃描時仍然保留這塊盤上的已有作品記錄。

同一部作品在幾個資料夾裡各有一份時，可以打開作品的「管理檔案」，從其他資料夾或遠端版本把需要的檔案集中到一個資料夾；「尋找重複檔案」會按內容標出完全相同的副本，確認後再刪除。

如果已經有自己有權存取的 Kikoeru 相容服務，也可以把它新增為遠端來源，瀏覽、播放或按需取回檔案。同一作品的本機、快取與遠端位置圍繞同一條作品記錄管理，收藏和收聽記錄不用跟著檔案位置重複建立。

遠端播放、快取和 Fetch 各有用途：播放是直接收聽，快取是保留可重建的媒體副本，Fetch 則把選定檔案儲存到自己的媒體目錄。只想整理本機作品的話，從一個音聲資料夾開始就夠了。

掃描、同步作品資訊、檔案獲取以及轉寫和翻譯等任務都以工作流的形式執行，進度和結果在「活動」裡檢視。需要定期掃描或同步作品資訊時，再在「工作流」裡設定自動執行規則；關注社團或聲優的新作品，則用前面提到的訂閱。

## 用 Docker 搭建自己的音聲庫

推薦直接用 Docker Compose 部署。需要準備一台能執行 Docker 的電腦或 NAS，以及已經儲存的音聲檔案。映像檔支援 `linux/amd64` 和 `linux/arm64`，ARM 架構的 NAS 和 64 位元 Raspberry Pi OS 也能執行。部署完成後，檔案和帳號資料都放在自己的裝置上，瀏覽器或客戶端負責存取。

```mermaid
flowchart TB
    A["電腦瀏覽器"] --> C["電腦或 NAS 上的 Kikoto"]
    B["手機瀏覽器或 Android / iOS 客戶端"] --> C
    C --- D["音聲資料夾"]
    C --- E["帳號、收藏與收聽記錄"]
```

Windows 上還有一個 [Kikoto Helper](https://github.com/yexca/kikoto-helper)，也能幫忙部署和管理 Kikoto，它現在在獨立的倉庫裡開發和發布。不過它**不是推薦的部署方式**，只適合實在沒辦法讓 Docker 正常執行的情況；能用 Docker 的話，照下面的步驟部署就好。Helper 的另一個用途是在本機執行語音辨識和翻譯模型，用 Docker 部署的 Kikoto 同樣可以接入。原本 Kikoto 倉庫裡的 `kikoto-helper.cmd` 指令碼已經不再維護。

### 準備 Docker 和部署目錄

Windows 可以安裝 [Docker Desktop](https://docs.docker.com/desktop/setup/install/windows-install/)；macOS 可以使用 [OrbStack](https://orbstack.dev/download) 或 Docker Desktop；Linux 按發行版安裝 [Docker Engine](https://docs.docker.com/engine/install/) 和 Compose 外掛程式。NAS 則使用系統提供的容器管理工具。

安裝後，先確認終端機能夠執行：

```sh
docker compose version
```

再建一個專門的部署資料夾，例如 Windows 下的 `D:\kikoto`。下載專案提供的 [docker-compose.yml](https://github.com/yexca/kikoto/blob/main/docker-compose.yml)，放進這個資料夾，並準備以下目錄：

```text
kikoto/
├── config/
├── cache/
├── data/
└── docker-compose.yml
```

`config` 儲存帳號、資料庫和收聽記錄，`cache` 儲存快取，`data` 預設用來放音聲。macOS 或 Linux 也可以在部署目錄中用下面的指令下載設定：

```sh
curl -fL https://raw.githubusercontent.com/yexca/kikoto/main/docker-compose.yml -o docker-compose.yml
```

### 告訴 Kikoto 音聲放在哪裡

打開 `docker-compose.yml`，找到 `volumes`。預設設定如下，這只是完整檔案中的一個片段：

```yaml
volumes:
  - ./config:/config
  - ./cache:/cache
  - ./data:/data
```

每行冒號左邊是電腦上的資料夾，右邊是容器裡看到的路徑。**如果音聲已經存在其他目錄，修改左邊的路徑即可，不必再複製一份。**

例如 Windows 的音聲放在 `D:\Audio`，改成：

```yaml
volumes:
  - ./config:/config
  - ./cache:/cache
  - "D:/Audio:/data"
```

macOS 或 Linux 同樣替換左邊的目錄，例如 `/mnt/audio:/data`。Windows 路徑使用 `/` 並加上引號，儲存時保留原檔案的縮排。

如果準備使用儲存池，則保留 `./data:/data`，再把各塊盤對映成 `/data/disk1`、`/data/disk2` 等子目錄，首次設定時選擇對應的池。具體設定可以參考[使用指南](https://github.com/yexca/kikoto/blob/main/docs/user/zh-Hans/getting-started.md#存储池)。

### 啟動並完成首次設定

在部署目錄打開終端機，先檢查設定，再啟動：

```sh
docker compose config --quiet
docker compose up -d
```

映像檔下載並啟動後，在這台電腦上打開 `http://127.0.0.1:7655`。首次存取會要求建立管理員，初始化令牌可以在日誌中找到：

```sh
docker compose logs kikoto
```

也可以讀取 `config/setup-token` 檔案。填入令牌，設定使用者名稱和密碼，然後跟著「設定媒體庫」引導完成：

1. 選擇普通模式或儲存池模式。
2. 掃描音聲目錄，找到本機作品。
3. 同步作品資訊，補齊封面和介紹。
4. 按需要開啟自動掃描與資料夾監視。

作品目錄名稱需要包含受支援的作品編號。如果掃描後什麼都沒有，先檢查目錄對映和資料夾名稱；封面暫時沒出現，則可以到「活動」裡看元數據同步的進度。

### 從手機存取

手機與部署裝置連到同一個區域網路後，用電腦的區域網路位址存取，例如 `http://192.168.1.23:7655`。這裡的位址要換成自己的；`127.0.0.1` 在手機上指的是手機本身。

Windows 可以用 `ipconfig` 檢視實際 Wi-Fi 或乙太網路介面的 IPv4 位址。連接不上時，再檢查電腦防火牆和路由器的訪客網路隔離。部署裝置需要保持執行。

Android 和 iOS 客戶端都在 [GitHub Releases](https://github.com/yexca/kikoto/releases) 裡：Android 下載 APK 安裝；iOS 提供的是未簽名的 IPA，需要用側載工具以自己的 Apple 帳戶簽名後安裝。打開客戶端，填寫同一個伺服器位址即可。

預設的埠號對映會監聽裝置上的所有網路介面，**不要把 Kikoto 直接暴露到公網**。只在本機使用時，可以把 `ports` 改成 `127.0.0.1:7655:7659`。需要在外面收聽時，先做好存取保護：例如只讓自己的裝置透過加密的私有網路（異地組網）連回家裡，或者在前面放一個帶 HTTPS 和身分驗證的反向代理。具體可以參考[安全說明](https://github.com/yexca/kikoto/blob/main/docs/operations/security.md)。

## 備份與日常維護

最值得儲存的是音聲原檔案，以及 `config` 裡的資料庫和個人資料。快取通常可以重建。Kikoto 也支援匯出、匯入個人的標記、評分、標籤、收藏列表和收聽進度，還能從 Kikoeru 匯入，換裝置或換實例時可以繼續使用。

更新前先看一下[發布說明](https://github.com/yexca/kikoto/blob/main/docs/history/index.md)，裡面會寫明需要留意的變化；再備份 `config`，以及 `docker-compose.yml`、`.env` 等部署設定。音聲目錄保持原本的對映，不用複製。然後在部署目錄執行：

```sh
docker compose up -d --pull always
```

這條指令會拉取最新映像檔並重建容器，資料庫會在啟動時自動升級。如果在 `.env` 裡用 `KIKOTO_IMAGE` 固定了版本，先改成新的版本再執行。

更多操作可以[查閱文件](https://github.com/yexca/kikoto/blob/main/docs/user/index.md)。
