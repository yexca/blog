# Project Structure

## Top Level

| Path | Responsibility |
| --- | --- |
| `content/` | Multilingual blog content. |
| `themes/hugo-theme-stack/` | Project-specific theme fork. |
| `hugo.yml` | Site, language, menu, output, and theme configuration. |
| `translation/` | Translation config and manifest state. |
| `scripts/` | Local maintenance scripts. |
| `static/` | Files copied directly to the published site. |
| `docs/` | Maintenance documentation. |
| `public/` | Generated site output. Do not edit by hand. |
| `resources/` | Hugo generated resources/cache. Do not treat as source. |

## Static Files

Everything in `static/` is published as-is. Keep this directory small and only
use it for files that must exist at a stable public path, such as `favicon.ico`
or `CNAME`.

Do not keep unused fonts, screenshots, drafts, source assets, or large
reference files in `static/`.

## Theme Source

The active theme code is split across:

- `themes/hugo-theme-stack/layouts/`: Hugo templates and partials.
- `themes/hugo-theme-stack/assets/scss/`: bundled SCSS.
- `themes/hugo-theme-stack/assets/ts/`: bundled TypeScript.
- `themes/hugo-theme-stack/i18n/`: theme UI translations.
- `themes/hugo-theme-stack/layouts/shortcodes/`: shortcode templates.

## Generated Output

`public/` should be regenerated by Hugo. If a bug only appears in `public/`,
trace it back to the template, asset, content, or config source before editing.
