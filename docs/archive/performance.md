# Performance

This document describes the current performance maintenance rules for the blog.

## Build And Report

Run the production build first:

```powershell
.\env\hugo\hugo.exe --gc --minify
```

Then run the report:

```powershell
& "C:\Users\yexca\.cache\codex-runtimes\codex-primary-runtime\dependencies\node\bin\node.exe" scripts\check-performance.mjs
```

The script reads `public/` and reports:

- total output size
- largest HTML files
- search JSON files
- CSS and JS bundles
- fonts
- feeds
- largest images

Budgets live in:

```text
scripts/performance-budgets.json
```

Budget warnings do not fail the command.

## Current Baseline

The first baseline report is:

```text
refactor/reports/performance-baseline-2026-06-07.md
```

After the first implementation pass, a clean production build reports:

- total output around 75 MB
- largest search index around 268 KB
- no generated font files
- no budget warnings

## Search

Search JSON is generated by:

```text
themes/hugo-theme-stack/layouts/page/search.json
```

It is a light index. It includes title, date, permalink, summary, description,
tags, categories, and optional image. It intentionally does not include full
article text.

The search page no longer preloads `search/index.json`. The JSON file should
only be requested after the user enters a keyword or opens a search URL with a
keyword parameter.

## Categories

The category index page is intentionally lightweight:

- category cards link to term pages
- the page renders preview panels for the first three categories
- each preview panel renders at most six posts
- full browsing uses `/categories/<term>/` with Hugo pagination

Do not reintroduce all category posts into `/categories/` unless the performance
budget is also updated.

## Images

Article pages use:

```text
themes/hugo-theme-stack/layouts/partials/article/components/header.html
```

Article list cards use:

```text
themes/hugo-theme-stack/layouts/partials/article-list/cover.html
```

Article page cover images keep larger responsive sizes and use eager loading
with high fetch priority. List cover images use smaller responsive sizes.

## Fonts

Large unused Yozai fonts are kept outside the published `static/` tree:

```text
docs/assets/fonts/
```

Files in `static/fonts/` are published directly. Do not put large unused fonts
there.

## Third-Party Scripts

Vibrant is only rendered on pages that contain tile cards needing image color
extraction. The color helper must tolerate Vibrant being unavailable.

Twikoo is rendered as a data container and loaded by:

```text
themes/hugo-theme-stack/assets/ts/features/twikooComments.ts
```

The script loads Twikoo when the comment container approaches the viewport.

GitHub info cards are loaded by:

```text
themes/hugo-theme-stack/assets/ts/features/githubInfoCards.ts
```

Cards request the GitHub API only after entering the viewport and cache results
in `sessionStorage`.

## Page Initialization

Page features are registered in:

```text
themes/hugo-theme-stack/assets/ts/core/pageInit.ts
```

Feature setup should be gated by selectors. New features should expose:

```ts
setupFeature(root?: ParentNode): void
```

Use element-level `data-stack-*-ready` flags for repeated soft navigation.
